# 0023 UI languages

Status: implemented
Reviewed: spec-reviewer, 2026-11-04
Depends on: 0001 (settings file, the 0001 strings), 0020 (Preferences), 0021 (Help, Keyboard Shortcuts), 0022 (announcements, names), 0026 (Picture tab)

## Why
Easel's users read Czech, German, Spanish, French, Hungarian, Italian, Polish, Portuguese, Romanian, Russian and Ukrainian as well
as English. The interface speaks their language, and English stays the default for everyone else.

## Requirements
- REQ-0023-01 The app shall offer its interface in twelve languages, listed by code in alphabetical order: cs Czech, de German, en English, es Spanish, fr French, hu Hungarian, it Italian, pl Polish, pt Portuguese (as in Brazil, pt_BR), ro Romanian, ru Russian, uk Ukrainian (locale uk_UA; JOD, 2026-10-27). Every string the app shows is translatable and is not built by concatenation (`docs/design.md`): window titles, menus, tooltips, hints, the status bar, dialogs, Keyboard Shortcuts, the Picture tab, announcements and accessible names, and the Help page (REQ-0023-09). GTK's own strings (the file and color choosers, the print dialog) follow GTK's translation of the same language, where the system has it.
- REQ-0023-02 English shall be the default (JOD, 2026-10-27): the source strings are English, English has no translation of its own and is never incomplete. The app shall show English (a) when the setting is `auto` and the system's language is not one of the twelve, and (b) for a single string a language lacks, that string only.
- REQ-0023-03 The system's language shall be the first of the user's preferred languages (the desktop's list) that is one of the
  twelve, matched by its language part: de_AT is German, pt_PT is Portuguese (the pt_BR translation), en_GB is English.
- REQ-0023-04 (Pointer note, Preferences buttons, 2026-11-04: group Language is on page Interface, before Panels, REQ-0027-01, and the row writes at OK or Apply, REQ-0027-07; without this note it directly follows group Style on page Appearance and writes at once.) Preferences' Appearance page shall have a group Language, directly after group Style (REQ-0020-03), with a row Language. Its first entry is "System default", which follows the system's language (English if that is not one of the twelve). After it come the twelve languages by their own names, which are not translated, always in the order of their codes (REQ-0023-01): Čeština, Deutsch, English, Español, Français, Magyar, Italiano, Polski, Português, Română, Русский, Українська. The settings file keeps the choice as `[interface]` `language=`: `auto` for System default, otherwise the code. A new settings file has `language=auto`. A missing or invalid value is `auto` (REQ-0001-05); the code's case is ignored (extends REQ-0001-40), and `pt_BR`, `uk_UA` and `de_AT` are invalid.
- REQ-0023-05 (Pointer note, Preferences buttons, 2026-11-04: the app also says so in a notice when the language is kept, REQ-0027-16; without this note it says only the subtitle.) A change of language shall take effect at the next start: the row's subtitle says "Takes effect the next time Easel starts.", as in REQ-0020-05. A chosen language shall show also where the system has no locale for it, and where the only locale installed is C (JOD, 2026-11-04). Numbers and dates keep the forms the app has ("100 %", "640 × 480") in every language, except Frame time's decimal mark, which follows the system's locale (REQ-0021-12).
- REQ-0023-06 A message with a count shall take the interface language's plural form for that count, each translation stating exactly this rule: de, en, es, hu, it: one for 1, other for the rest. fr, pt: one for 0 and 1, other for the rest. cs: one for 1, few for 2 to 4, other for the rest. pl: one for 1; few for numbers ending in 2 to 4, except those ending in 12 to 14; many for the rest. ru, uk: one for numbers ending in 1, except those ending in 11; few as in pl; many for the rest. ro: one for 1; few for 0 and for numbers whose last two digits are 01 to 19; other for the rest. A message with two numbers (W × H) takes the form of the last number.
- REQ-0023-07 Each translation, with its Help page, shall say in its own header whether it has been reviewed. Every translation starts as a draft; Russian, Ukrainian and Polish are reviewed by JOD, and the table under Edge cases records the date; the other eight stay marked unreviewed (JOD, 2026-11-04). The mark is for translators: the app shows nothing of it, and every language is offered alike.
- REQ-0023-08 The twelve include no right-to-left language; the layout shall never be mirrored, also on an Arabic or Hebrew system, where the interface is English (JOD, 2026-10-27).
- REQ-0023-09 The Help page (REQ-0021-04) shall open in the interface's language, with the same parts and every key of Keyboard Shortcuts, the row titles as Keyboard Shortcuts shows them, and the key names as in English. A language whose page is missing opens the English page; if that is missing too, the error of REQ-0021-04 shows.
- REQ-0023-10 Every translation shall have every message: none missing, empty or marked uncertain. The checks in `meson test`, not the build itself, shall fail on such a message, on a placeholder that differs from the source's, on a missing plural form, and on a bad header or a plural rule other than REQ-0023-06's. If a translation lacking a message is installed anyway, that message shows in English (REQ-0023-02).
- REQ-0023-11 In a long test language, never offered to users, in which each string is as long as the longest of its German and Russian forms, the main window's minimum size and each dialog's natural size shall fit 1024 × 768 logical pixels, a scrolled page by its width only; the toolbox and the tool options shall keep their widths' layout; the Picture tab shall fit too, measured on its own; and every label shows whole, except the status bar's hint and the font card's family, which end in an ellipsis.

## Edge cases
- The chosen language's system locale is not installed (ru_RU missing): the interface is still in that language; GTK's own dialogs follow what the system has.
- A number in a sentence: its plural form follows REQ-0023-06, its digits stay Western in every language.
- A language's reviewed mark is set when JOD has read it. 0023 may be implemented before that (JOD, 2026-11-04: accepted, the thorough reading comes later); until then ru, uk and pl stay marked unreviewed, and the reading is a known gap.
- The suggested file name follows the translated "Untitled".
- Changed decision (JOD, 2026-11-04). Old (2026-10-27): the list sorted "with the collation of the interface's current language". New: the order of the language codes, fixed in every interface language, since a collation needs a locale the system may not have.
- The only locale installed is C: choosing any of the twelve still shows that language (REQ-0023-05, AS-8).

## Out of scope
- Right-to-left languages; mirroring (REQ-0023-08); numbers and dates in the locale's form; a change of language at once; the desktop file's and AppStream's translations (Packaging and Release); the long test language in the app's list.

## Open questions

## Plan
**Approach.** The app reads its own compiled translations, for one code path on every machine: a probe shows gettext returns the source under `C` and `C.UTF-8` even with `LANGUAGE` set (glibc 2.44), so REQ-0023-05 cannot rest on it. A core reader looks up a message in a compiled catalog and a core table holds each language's plural rule. Strings in C go through `_()` and `_n()`. `window.ui` is translated as text before GTK reads it, so no builder or gettext is involved. GTK's own strings go on through gettext, with `LANGUAGE` set, and follow what the system has.

**Files.** New: `src/core/catalog.{c,h}` (the reader, plural rules, translating a template's text), `src/ui/i18n.{c,h}` (choosing the language, finding the catalog and page, `_()`), `po/` (`LINGUAS`, `POTFILES`, `easel.pot`, eleven `.po`, `meson.build`), `data/help/<code>/index.html`, `tools/check-translations.py`, `tools/po-long.py`, `tests/core/test-catalog.c`, `tests/data/po/` (bad translations for the check). Changed: every `src/ui/*.c` with strings, `src/ui/window.c`, `src/ui/help.c`, `src/ui/preferences-dialog.c`, `src/core/settings.{c,h}`, root `meson.build`, `tests/meson.build`, `tests/ui/test-window.c`, `tests/mutants.txt`.

**Key interfaces.**
- Core: `EaselCatalog *easel_catalog_new (const void *mo, size_t len)`, `const char *easel_catalog_get (cat, msgid)`, `const char *easel_catalog_get_plural (cat, msgid, msgid_plural, n, lang)`, `int easel_plural_form (const char *lang, unsigned long n)`, `char *easel_catalog_translate_ui (cat, xml)`.
- Ui: `easel_i18n_init (language)`, with `const char *_()` and `_n()` carrying the format attribute so that `-Wformat=2` still checks a translated format. `easel_i18n_choose (setting)` over core `easel_language_resolve (setting, names)`: REQ-0023-02, -03.
- Tests: `EASEL_TEST_LANGUAGE` picks the language for a process, the long test language included; `EASEL_LOCALE_DIR` the folder, else the build's copy beside the program, else where it was installed (as the Help page).

**The one function.** `easel_i18n_init`, once, before any window class is made: the template and the strings cannot change afterwards, which is why a change takes effect at the next start.

**Language per process.** Each language is a run of its own: `ui-0023-<code>` runs the cases of `/0023-lang` with `EASEL_TEST_LANGUAGE`. Every other ui test runs with `EASEL_TEST_LANGUAGE=en` in `ui_env`, `ui_a11y_env` and `ui_vulkan_env` (AS-13). The only-C run sets `LOCPATH` to nothing and starts in a language.

**Readers of what this extends.**
- `tests/mutants.txt`: mutants whose find text holds a marked string; `--lint` lists them.
- `.scratch` runners and `tools/mutate.sh`: they use `meson test`'s env or set their own; the runners get `EASEL_TEST_LANGUAGE=en`.
- `[interface]` is a new settings section: `easel_settings_parse`, `easel_settings_default_text`, 0001's AS-4, 0004's AS-14, 0020's AS-13.

**What grows.** One catalog in memory for the process, the size of its compiled file, read once. Translated strings point into it, so nothing is copied per lookup.

**Constitution.** Core stays libc only; no ADR: the reader replaces nothing the constitution names.

**Risks.**
- R1 A template translated before GTK reads it: all its marked strings are plain text in elements, with entities; `as12_no_english` and the core test of the entities check it, T003.
- R2 `-Wformat=2` on a translated format: a format attribute on `_()`, seen in the first build of T003.
- R3 GTK's dialogs and libadwaita's strings stay English where the system has no catalog: allowed by REQ-0023-01.
- R4 A format with a word of another language in a placeholder: `tool-options.c`'s `"%s, %d pixels"` and the print of a color square become whole sentences, T003.
- R5 `src/core/rich-text.c` parses numbers with locale-sensitive calls, and a chosen language sets no numeric locale of its own: unchanged by this spec, as `LC_NUMERIC` comes from the system as before.
- R6 Drafted translations can be wrong in ways tests cannot see: only JOD's reading of ru, uk and pl settles those (M2).
